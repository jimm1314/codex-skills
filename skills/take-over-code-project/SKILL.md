# 项目接管与上下文恢复

## 基本原则

1. 使用通俗中文，把结论标记为`已确认`、`合理推断`或`待确认`。
2. 事实优先级固定为：

   ```text
   当前真实源码 / Git > CODEX_HANDOFF.md > 历史对话或 Skill 假设
   ```

3. `CODEX_HANDOFF.md` 是状态索引，不是事实替代品；读取后必须用 Git 和相关源码验证。
4. 默认按需读取。不要递归扫描整个仓库，不要为了“全面”读取所有源码、日志、生成物或依赖目录。
5. 不重复读取已确认且未变化的大文件。信息不足时从当前任务相关文件逐步向调用方、被调用方、测试和配置扩大。
6. 用户未授权修改时只分析。不得泄露凭据、连接生产环境或执行危险操作。

## 选择模式

只进入一个主模式：

- **Session Resume**：用户说“继续”“接着上次”，或项目存在 `CODEX_HANDOFF.md`。读取 [references/session-resume.md](references/session-resume.md)。
- **首次 Onboarding**：用户第一次接触项目，需要理解、安装或运行，且没有可用 Handoff。读取 [references/first-onboarding.md](references/first-onboarding.md)。
- **调用链追踪**：用户已经给出具体功能、Bug 或需求。先完成最小状态检查，再只追踪相关链路。

用户目标变化时可以切换模式，但不要重新执行已经确认且仍有效的阶段。

## 最小状态检查

在已有本地仓库中：

1. 如果存在 `CODEX_HANDOFF.md`，先读一次。
2. 检查当前 branch、`git status` 和最近 `git log`。
3. 只有存在未提交修改时才读取对应 `git diff`；先看文件列表或 `--stat`，再按需读具体 diff。
4. 检查当前作用域适用的 `AGENTS.md` 或同类项目规则。
5. 根据用户目标和 Handoff 的“关键文件/下一步”读取最少源码。
6. 用简短状态摘要说明：当前目标、分支、未提交修改、已确认进展、风险和建议下一步。

上述检查是只读诊断，不自动 fetch、pull、merge、rebase、commit 或 push。

## 调用链追踪

按项目真实结构还原，不强行套层级：

```text
用户入口 → 页面/命令/事件 → 接口或路由 → 核心逻辑
→ 数据/外部服务 → 返回结果 → 测试与验证
```

输出只包含：

1. 相关文件与关键符号；
2. 调用顺序和关键数据变化；
3. 已确认事实、待确认环节；
4. 可能的修改点；
5. 影响范围与建议验证；
6. 下一步应交给哪个 Skill。

不要粘贴完整源码；引用路径、符号和必要短片段即可。

## 路由边界

- 用户确认要实现、修复、重构或审查代码：转入 `$engineer-code-safely`。
- 用户要改变分支、提交、同步、合并、推送或回滚：转入 `$guide-gitlab-safely`。
- 用户明确要求结束 Session、维护交接文件：转入 `$session-handoff`。
- 当前 Skill 只负责建立可信项目上下文，不把理解项目自动扩展为修改授权。

## 输出控制

- 首轮优先给一份短状态摘要，不默认输出完整项目百科。
- 项目地图只展示关键目录和一条代表性链路。
- 日志默认读取错误附近和末尾必要行；只有证据被截断时才扩大。
- 每轮只展开当前目标最相关的内容，并给一个明确下一步。
