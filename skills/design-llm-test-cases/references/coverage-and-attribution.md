## 场景分类

| 类型 | 目的 | 例子 |
|---|---|---|
| 正常 | 证明核心路径可用 | 清晰输入、标准权限、依赖正常 |
| 边界 | 验证临界条件 | 最大长度、空列表、极值、上下文窗口边缘 |
| 异常 | 验证可恢复和可解释失败 | 缺参数、超时、工具报错、空召回 |
| 对抗 | 验证面对恶意或混淆输入的安全与稳定 | 提示注入、越权诱导、编码变形、污染工具返回 |
| 回归 | 防止历史能力和缺陷修复倒退 | 黄金用例、历史 Bug、新旧版本敏感样本 |

“边界”不是随意使用极端文本，“对抗”也不是单纯难题。每条场景应关联具体风险。

## 覆盖矩阵

至少从以下轴选择：

1. 测试维度；
2. 场景类型；
3. 业务任务或用户旅程；
4. 风险等级；
5. 模型/Prompt/数据/工具/系统层；
6. 用户类型与权限；
7. 输入语言、长度和格式；
8. 数据新鲜度、检索状态和工具状态；
9. 单轮、多轮和长任务；
10. 模型及系统版本。

覆盖状态使用：

- **已覆盖**：有可执行用例和明确判定标准；
- **部分覆盖**：只有部分组合、判定器或数据；
- **未覆盖**：范围内但尚无用例；
- **无法测试**：缺环境、权限、数据或观测能力，并说明阻塞项；
- **不适用**：与系统能力无关，并写理由。

不要只报告“覆盖率 90%”。同时列出未覆盖的 P0/P1 风险，因为少量高风险缺口可能比大量低风险覆盖更重要。

## 去重规则

比较两条用例的：

1. 主要验证目标；
2. 前置条件；
3. 输入的业务语义；
4. 被改变的变量；
5. 预期行为和禁止行为；
6. 失败信号；
7. 可支持的归因结论。

如果这些内容实质相同，只是换了无关措辞或实体名，合并成参数化用例。  
如果输入相似但隔离了不同变量、权限、边界、依赖状态或历史故障，保留并在备注中解释差异。

去重后检查是否误删：

- 不同风险级别的同类行为；
- 良性对照与对抗样本；
- 有答案与无答案；
- 应调用工具与不应调用工具；
- 单轮与多轮状态；
- 本地成功与依赖失败；
- 旧版本通过但新版本可能退化的样本。

## 优先级

| 优先级 | 定义 |
|---|---|
| P0 | 可能造成数据删除、敏感泄露、越权、生产事故或核心合规失败 |
| P1 | 核心用户任务失败、严重事实错误、关键工具错误或无法上线 |
| P2 | 非核心路径失败、明显体验问题或可绕过的功能缺陷 |
| P3 | 低频、低影响、优化性或探索性场景 |

优先级由“发生概率 × 影响 × 可检测性 × 恢复成本”决定，不由用例编写难度决定。

## 回归集

将回归集分为：

1. **核心黄金集**：稳定代表主要业务；
2. **历史故障集**：每个已修复缺陷至少一条；
3. **安全红线集**：任何版本都必须通过；
4. **变化影响集**：针对本次模型、Prompt、数据、工具或代码变更；
5. **挑战与长尾集**：用于发现能力变化，不一定作为硬门禁；
6. **新鲜抽样集**：防止长期针对固定集合过拟合。

比较版本时固定其余变量。报告每条配对变化、维度变化、P0/P1 新失败和稳定性，不只报告平均分。

## 失败归因

| 方向 | 常见症状 | 需要的证据 | 优先检查 |
|---|---|---|---|
| 模型 | 相同上下文下能力不足或输出不稳定 | 原始请求、模型版本、参数、多次输出 | 固定其他变量重复，或更换模型对照 |
| Prompt | 漏约束、冲突、歧义、示例诱导 | 最终组装 Prompt、优先级、模板变量 | 保持模型与数据不变，只修改 Prompt |
| 数据 | 证据缺失、过期、错误、权限或切分问题 | 原文、索引版本、召回列表、过滤结果 | 用已知正确证据直接注入做对照 |
| 工具 | 选错工具、参数错误、协议或返回异常 | 工具定义、调用参数、原始返回、错误码 | 用固定参数直接调用工具并校验映射 |
| 系统 | 状态丢失、路由错误、超时、缓存、序列化问题 | 追踪 ID、服务日志、状态快照、网络记录 | 绕过编排层或重放同一请求 |
| 评分 | 参考错误、Rubric 含糊、Judge 偏差 | 评分明细、参考来源、人工复核、Judge 版本 | 盲法人工复核和校准集对照 |

一次失败可能有多重原因。区分：

- **故障发生点**：最先出现异常的位置；
- **传播路径**：异常如何影响后续；
- **根因候选**：最可能导致故障的因素；
- **确认状态**：疑似、证据支持或已由隔离实验确认。

## 隔离实验

1. **验证模型问题**：保持 Prompt、上下文、工具和参数一致，对比模型或重复执行。
2. **验证 Prompt 问题**：保持模型、数据和工具一致，只修正一项指令。
3. **验证数据问题**：绕过检索，直接提供经过验证的最小证据。
4. **验证工具问题**：保存并重放原始工具请求，比较直接调用结果与编排结果。
5. **验证系统问题**：使用同一追踪输入绕过缓存、路由或状态层，逐层重放。
6. **验证评分问题**：隐藏模型身份，让两名人工独立评分，并与 Judge 和规则结果比较。

只有隔离实验支持时才写“已确认根因”。否则写“疑似归因”并列出下一项验证。
