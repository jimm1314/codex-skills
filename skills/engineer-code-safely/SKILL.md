# 安全代码工程与审计

## 工作底线

1. 先确认用户授权终点。只分析、规划或审查不等于获准修改；修复问题也不自动包含 commit、push 或合并授权。
2. 使用通俗中文，但保持项目原有工程标准。
3. 结论标记为`已实际验证`、`仅静态检查`、`合理推断`、`尚未验证`或`需要人工确认`。
4. 优先最小、相关、可验证的修改，不覆盖用户已有改动，不顺手重构、升级依赖或批量格式化无关文件。
5. 不伪造文件、接口、日志、测试、运行结果或安全结论。

## 项目上下文门禁

进入已有仓库时使用最小上下文：

1. 若存在 `CODEX_HANDOFF.md`，先读一次。
2. 检查当前 branch、`git status` 和最近 `git log`。
3. 只有存在未提交修改时，先看 diff 文件列表或 `--stat`，再读取相关 diff。
4. 读取当前路径适用的 `AGENTS.md` 或同类规则。
5. 从 Handoff 的关键文件和当前需求直接相关的实现、测试、配置开始；证据不足时沿调用链逐步扩大。
6. README、CONTRIBUTING、依赖清单、入口、CI 和全局架构只在影响本次需求时读取，不作为每次 Session 的固定全量清单。

事实优先级：

```text
当前真实源码 / Git > CODEX_HANDOFF.md > 历史对话或 Skill 假设
```

如果尚未建立可信项目上下文，先使用 `$take-over-code-project`，不要在本 Skill 中重复扫描整个仓库。

## 选择流程强度

| 级别 | 适用情况 | 最小流程 |
|---|---|---|
| A | 单点配置、小函数、已知根因的局部 Bug | 目标 → 相关代码 → 最小修改 → 定向验证 → 简版审计 |
| B | 新接口、多个关联文件、测评脚本、调用链变化 | 关键澄清 → 简版契约 → 计划 → 实现 → 测试 → 关联审计 |
| C | 新系统、跨服务、Agent/RAG、数据迁移或高不确定性 | 方案比较 → 完整契约 → 分阶段实现 → 集成验证 → 完整审计 |

选择最轻但足够安全的流程，不为简单改动强制生成完整 Spec 和长报告。

## 工程流程

### 1. 明确目标

- 复述业务目标、非目标和可观察的成功标准。
- 只在缺失信息会改变范围、数据、接口、安全、兼容性或验收标准时提问。
- 多个实质方案并存时比较实现难度、风险和维护成本；不可逆或架构级决定等待确认。

### 2. 契约与计划

- B/C 级任务按需读取 [references/spec-template.md](references/spec-template.md) 中相关章节，不必默认全文加载。
- 涉及模块或外部系统时明确调用方、输入输出、错误、超时、幂等、兼容和数据副作用。
- 计划拆成可验证的小步骤，写清文件、依赖、完成标准和风险。

### 3. 实现或修复

- 遵守现有命名、架构、错误处理和测试风格。
- 默认不信任外部输入；按真实攻击面处理注入、权限、路径、文件和敏感信息。
- 只捕获能够处理或补充上下文的异常，保留错误链并释放资源。
- 修复 Bug 时尽可能先建立失败测试或最小复现，再做最小修复。
- 只在有真实需求时加入重试、事务、锁、抽象层或监控。

### 4. 系统化调试

按顺序收集错误、确认复现、定位数据流、区分根因与症状、一次验证一个主要假设、建立最小复现、最小修复并运行回归。连续三次方向失败时停止盲试，重新检查环境、架构和假设。

### 5. 验证与审计

- 先说明命令要证明什么，再运行与改动直接相关的测试、构建、类型、Lint、格式或最小业务验证。
- 退出码为 0、页面打开或接口返回 200 只能证明局部事实。
- 按改动风险读取 [references/audit-checklist.md](references/audit-checklist.md) 的相关章节；B/C 或高风险改动再执行完整五维审计。
- 无法验证时说明阻塞原因、已覆盖范围和补充验证路径，不得声称“已修好”。

### 6. 交付

- 实际交付代码后按需读取 [references/beginner-delivery.md](references/beginner-delivery.md)，只输出与本次改动相关的运行、验证和风险。
- 涉及跨模块/API/数据契约时读取 [references/interface-integration.md](references/interface-integration.md)。
- 涉及分支、同步、提交、合并、推送或回滚时使用 `$guide-gitlab-safely`；本 Skill 不复制 Git 操作规则。
- 用户要求结束 Session 或更新交接时使用 `$session-handoff`。

## 安全边界

- 不输出真实 Token、密码、密钥、Cookie、内部凭据或生产连接值。
- 未经确认不连接生产环境、不删除数据、不覆盖配置、不关闭安全检查。
- 未经明确授权不 commit、push、merge、rebase、reset 或清理文件。
- 不把公司代码、日志或数据上传到外部服务。

## Reference 路由

- B/C 级需求、契约、数据流和任务计划：`references/spec-template.md` 的相关章节。
- 代码审计：`references/audit-checklist.md`；按风险决定局部或完整读取。
- 实际代码交付：`references/beginner-delivery.md`。
- 跨模块接口与发布兼容：`references/interface-integration.md`。
- 不读取当前阶段用不到的 reference，不把模板原样全部输出。
