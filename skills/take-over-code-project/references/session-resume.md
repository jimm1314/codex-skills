# Session Resume

仅在已有项目的新 Session 接手时读取。

## 恢复顺序

1. 读取项目根目录的 `CODEX_HANDOFF.md`；不存在时说明并改走首次 Onboarding 或最小项目分析。
2. 检查当前 branch。
3. 执行 `git status`。
4. 查看最近 `git log`。
5. 仅在存在未提交修改时查看 `git diff --stat`，再按需查看具体 diff。
6. 对照 Handoff 核对：
   - 当前目标是否仍有效；
   - HEAD、未提交修改和远端关系是否变化；
   - Handoff 列出的关键文件是否仍存在；
   - 已知风险和下一步是否已过期。
7. 根据当前任务读取 Handoff 指向的最少源码、配置和测试；信息不足时再沿直接调用链扩大。
8. 确认状态后再进入开发、Git 操作或继续分析。

不要默认 fetch，也不要为了验证 Handoff 扫描整个仓库。

## 冲突处理

发现冲突时按以下优先级纠正：

```text
当前真实源码 / Git > CODEX_HANDOFF.md > 历史对话或 Skill 假设
```

- Handoff 过时：指出具体过期项，但不要在 Resume 阶段擅自改文件。
- 工作区有 Handoff 未记录的修改：先识别修改归属和范围，不覆盖、不丢弃。
- 分支与 Handoff 不同：停止沿旧计划修改，先汇报当前分支和可能影响。
- Git 状态无法证明远端最新：明确写“远端状态尚未刷新”，不要猜测。

## 恢复摘要

控制在能支撑下一步的长度，包含：

- 当前目标；
- 当前 branch 和 HEAD；
- 工作区是否干净；
- Handoff 与真实状态是否一致；
- 本轮读取的关键文件；
- 当前风险或待确认项；
- 推荐的唯一下一步。

不要复述完整 Handoff，也不要重新输出完整项目地图。
