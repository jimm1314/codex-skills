# 接口、模块与发布集成

本文件只处理代码和数据契约。Git 分支、提交、同步、合并、推送和回滚统一使用 `$guide-gitlab-safely`。

## 适用范围

仅在改动跨越以下边界时读取：

- 前端与后端；
- 服务与服务；
- Agent 与工具；
- 应用与数据库；
- 项目与外部 API；
- 生产者与消费者；
- 新旧版本或分阶段发布。

## 契约检查

| 维度 | 需要确认 |
|---|---|
| 调用方 | 哪些页面、服务、脚本、Agent 或外部系统调用 |
| 请求 | 字段名、类型、必填、默认值、枚举、单位、编码 |
| 响应 | 结构、状态码、错误、空值、分页 |
| 行为 | 超时、重试、幂等、事务和副作用 |
| 数据 | Schema、迁移、默认值、历史数据和回滚 |
| 兼容 | 旧字段、旧调用方、版本号和适配层 |
| 发布 | 先后顺序、灰度、开关、观测和恢复 |
| 验证 | 契约测试、示例载荷、集成测试和业务结果 |

接口一侧测试通过不代表端到端一致；至少逐字段核对，并尽可能使用契约或集成测试。

## 兼容演进

破坏性变更优先采用：

1. 服务端同时支持新旧契约；
2. 升级调用方；
3. 观测旧调用是否消失；
4. 再删除旧契约。

无法兼容时明确版本、发布窗口、受影响调用方和恢复路径，并取得负责人确认。

## 集成验证

按风险选择：

- 编译、类型或 Schema 检查；
- 生产者/消费者契约测试；
- 真实示例载荷；
- 跨模块集成测试；
- 数据迁移升级与回退验证；
- 超时、错误和部分失败路径；
- 关键业务结果和可观测性。

说明尚未在 CI、测试环境、真实依赖或生产流量中验证的部分。

## 交付摘要

只报告：

- 变更的契约；
- 受影响调用方；
- 兼容策略；
- 发布顺序；
- 验证证据；
- 未覆盖风险和恢复条件。
