# 首次项目 Onboarding

仅在用户第一次接触项目、没有可用 Handoff，并且确实需要理解或运行项目时读取。

## 先确认目标

只确认无法从工作区得出的关键信息：

- 用户当前优先目标：理解结构、首次运行、解决启动错误或定位功能；
- 本地是否已有完整代码；
- 操作系统或权限是否会实质影响下一步。

不要重复询问路径、系统或目标等已知信息。

## 渐进式项目地图

先检查最小证据集：

1. 当前作用域的 `AGENTS.md`、README 或贡献说明；
2. 根目录和主要模块名称；
3. 与启动有关的依赖清单、锁文件和脚本；
4. 应用入口及一条代表性业务链；
5. 当前目标直接相关的配置和测试。

只有当前目标需要时，才继续检查数据库迁移、容器、CI、部署、全部子系统或外部服务。

输出一份精简地图：

- 项目解决什么问题；
- 关键技术及其在本项目中的职责；
- 关键目录；
- 一条代表性数据/请求链路；
- 推荐阅读顺序；
- 暂时可以忽略的目录；
- 依据文件与尚未确认的信息。

不要逐个罗列文件，也不要默认递归扫描仓库。

## 首次运行

按项目真实脚本逐步确认：

1. 运行时与包管理器版本；
2. 依赖安装方式；
3. 配置模板和必需变量名；
4. 数据库、容器或外部服务是否必需；
5. 最短启动命令；
6. 可观察的成功标准；
7. 安全停止和下次启动方式。

一次只推进一个会改变电脑或项目状态的动作。执行安装、写配置、迁移、开放端口或启动外部服务前，解释影响并取得授权。

不要要求用户粘贴真实密钥；只讨论变量名、用途和获取渠道。

## 风险检查

只报告有证据或与当前启动路线直接相关的风险：

- 版本、锁文件和操作系统兼容；
- 缺失配置或被忽略的必要本地文件；
- 私有依赖、网络、代理、权限；
- 数据库、端口和启动顺序；
- 文档、脚本与实际实现不一致；
- 生产配置或敏感信息误用。

每条写明证据、触发条件、影响和验证方式。没有证据时标为待确认，不为填满清单制造风险。

## 单步执行模板

用户需要亲自执行时，仅给当前一步：

- 目的；
- 操作位置；
- 一条命令或动作；
- 正常结果；
- 最短验证；
- 失败时需要返回的必要输出。

默认只请求错误附近和最后 10～30 行；证据不足时再请求完整错误链。
