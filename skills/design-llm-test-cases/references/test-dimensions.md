## 选择原则

- 从产品实际声明、用户任务和失败损失反推测试维度，不要求每次覆盖全部维度。
- 将“能力表现”与“系统机制”分开。例如 RAG 答错可能来自检索、上下文编排或生成。
- 为每个维度定义可观察信号、最低通过条件和不在范围内的内容。
- 先覆盖高频核心路径、高损失路径和历史故障，再扩充长尾组合。

## 基础模型与对话能力

| 维度 | 重点验证 | 场景种子 | 建议信号 |
|---|---|---|---|
| 基础问答 | 相关、正确、完整、简洁及合理拒答 | 常识、业务概念、信息不足、歧义问题 | 要点命中、事实错误数、澄清率、无依据断言率 |
| 指令遵循 | 完成显式任务并遵守格式、长度、语气和优先级 | 多约束、否定约束、冲突指令、分步任务 | 约束满足率、硬规则违规数、遗漏项 |
| 事实准确性 | 可核验陈述与权威来源一致 | 时间敏感事实、实体属性、数字、比较 | 事实级准确率、证据覆盖率、过期事实率 |
| 幻觉 | 在无证据或证据不足时不编造 | 虚构实体、错误前提、知识库空召回、不可访问链接 | 无依据断言率、正确纠错率、合理不确定性 |
| 安全性 | 拒绝或安全转换高风险请求，同时不过度拒绝正常请求 | 越权、隐私、危险操作、绕过表达、良性相邻任务 | 攻击成功率、拒绝准确率、过度拒绝率、泄露率 |
| 多轮对话 | 记住有效上下文、处理修正、维持目标并避免错误继承 | 指代、省略、话题切换、用户更正、长轮次 | 状态保持率、更正采纳率、上下文污染率 |
| 上下文理解 | 正确使用给定材料并区分指令与数据 | 多文档、矛盾证据、噪声段落、嵌套引用 | 证据使用率、矛盾识别率、错误归因数 |
| 长文本处理 | 在长输入中检索、总结、比较并保持覆盖 | 关键信息位于开头/中间/结尾、跨段依赖、超窗口输入 | 要点召回率、中部信息遗漏率、压缩失真率 |

### 基础问答

- 同时测试有唯一事实答案、允许多种表达的解释题，以及信息不足时的澄清或拒答。
- 不把字符串完全一致当成所有问答的通过条件。

### 指令遵循

- 将每条约束拆成可评分原子项。
- 分开测试“理解约束”和“执行约束”，避免一条复杂用例无法定位失败。
- 测试系统、开发者、用户和工具返回内容之间的优先级，但不得在用例中放入真实秘密。

### 事实准确性与幻觉

- 记录事实验证来源、版本和截止时间。
- 将错误分为无依据新增、与证据冲突、数字错误、实体混淆、引用不存在和不当确定语气。
- 测试模型能否指出错误前提，而不是顺着错误前提继续编造。

### 安全性

- 同时覆盖直接请求、角色扮演、编码或拼写变形、多轮渐进和工具间接注入。
- 加入良性对照组，衡量过度拒绝。
- 使用合成标识符和无实际危害的测试载荷，不输出可用密钥或真实攻击目标。

### 多轮、上下文与长文本

- 明确每轮允许使用的记忆、应忘记的信息和用户修正后的最新状态。
- 对长文本控制文档长度、关键信息位置、噪声比例和冲突程度。
- 分别评分信息找到、事实理解、跨段推理、引用定位和最终表达。

## 结构化输出与工具

| 维度 | 重点验证 | 场景种子 | 建议信号 |
|---|---|---|---|
| 结构化输出 | 语法、Schema、字段语义和约束 | 必填/可选字段、枚举、嵌套、转义、空值 | 解析成功率、Schema 通过率、字段语义准确率 |
| Function Calling | 是否调用、选择函数、参数构造及错误恢复 | 无需调用、多个候选函数、缺参数、非法参数、工具报错 | 调用决策准确率、函数选择率、参数准确率、恢复率 |
| MCP/工具调用 | 工具发现、权限、协议、资源使用和跨工具编排 | 工具不可用、权限拒绝、返回污染、超时、重复副作用 | 任务成功率、无效调用数、越权率、重复副作用率 |

### 结构化输出

- 先做解析和 Schema 硬检查，再评分字段语义。
- 覆盖多余文字、Markdown 包裹、转义字符、Unicode、极值、未知字段和字段顺序不应相关等情况。
- 对严格协议明确是否允许自动修复；不要默认为解析器会容错。

### Function Calling

- 测试正确的“不调用工具”，避免只统计调用成功样本。
- 检查函数名、必填参数、类型、枚举、默认值、单位、时间和实体消歧。
- 区分模型构造错误、工具描述歧义、编排器映射错误和工具业务失败。
- 对有副作用的函数验证确认、幂等键、权限和重复调用保护。

### MCP 或其他工具调用

- 覆盖能力发现、资源读取、提示模板、工具调用、权限失败和服务端错误。
- 将工具返回内容视为不可信数据，测试其中的提示注入和伪造指令。
- 对多工具任务记录计划、选择理由、调用顺序、参数、原始返回和最终整合。

## RAG 与 Agent

| 维度 | 重点验证 | 场景种子 | 建议信号 |
|---|---|---|---|
| RAG | 查询理解、检索、重排、证据使用、引用和拒答 | 同义问法、多跳、过期文档、冲突文档、空召回、权限文档 | Recall@k、MRR、证据覆盖率、忠实度、引用正确率 |
| Agent | 规划、执行、状态、恢复、停止和权限 | 长任务、部分失败、计划变化、循环诱因、副作用操作 | 任务成功率、步骤效率、恢复率、循环率、越权率 |

### RAG

分层测试：

1. **语料层**：文档正确、最新、可授权且可追溯；
2. **切分与索引层**：关键信息未被错误切断，元数据和权限过滤正确；
3. **检索层**：目标证据进入候选集；
4. **重排层**：最相关证据排在可用位置；
5. **生成层**：答案只依赖有效证据，能够处理冲突和无答案；
6. **引用层**：引用真实存在、支持相邻陈述且定位正确。

不要只测最终答案。保留查询改写、召回列表、分数、过滤结果、最终上下文和引用映射，以便归因。

### Agent

分开测试：

- 目标理解与任务分解；
- 计划是否可执行以及能否根据新证据调整；
- 工具选择、参数和调用顺序；
- 工作记忆、长期状态和多轮恢复；
- 超时、失败、部分成功和人工接管；
- 完成条件、停止条件、循环与资源预算；
- 有副作用动作前的权限、确认、预览和回滚。

端到端成功之外，还记录无效步骤数、重复调用、资源成本、恢复策略和错误传播位置。

## 代码、中文、鲁棒性与回归

| 维度 | 重点验证 | 场景种子 | 建议信号 |
|---|---|---|---|
| 代码生成 | 需求正确性、可运行性、质量、安全和修改范围 | 新函数、修 Bug、重构、跨文件、依赖限制 | 编译率、测试通过率、安全规则违规、补丁最小性 |
| 中文能力 | 中文语义、表达、指令、文化与格式 | 简繁体、歧义、成语、口语、专业术语、中英混排 | 语义准确率、术语一致性、病句率、格式遵循率 |
| 鲁棒性和对抗 | 对扰动、噪声、注入和分布变化保持稳定 | 错别字、Unicode、顺序变化、无关文本、恶意上下文 | 性能下降幅度、攻击成功率、稳定率 |
| 模型版本回归 | 新版本不破坏关键与历史能力 | 黄金集、历史 Bug、变化功能、随机重复 | 通过率差异、配对胜率、显著性、关键失败数 |

### 代码生成

- 优先用编译、类型检查、单元测试、集成测试、静态分析和安全扫描评分。
- 检查是否满足依赖、语言版本、性能和改动范围约束。
- 对修复任务加入原始失败测试、回归测试和不应变化的行为。
- 不执行来源不明或高风险代码；使用隔离环境和资源限制。

### 中文能力

- 覆盖简体、繁体、中英混排、数字单位、日期、标点、称谓、歧义和上下文省略。
- 对术语翻译、行业表达、语气和地区差异分别评分。
- 不以文风偏好掩盖事实或指令错误。

### 鲁棒性和对抗

- 对同一语义生成受控扰动，比较输出质量下降，而不是用完全不同问题做对比。
- 覆盖拼写、空白、大小写、字符编码、段落顺序、噪声和提示注入。
- 保留未扰动基线，记录最坏情况、均值和稳定率。

### 模型版本回归

- 固定 Prompt、工具、数据、参数和评分器版本，只改变待比较变量。
- 结合黄金集、历史故障集、核心业务集、安全集和随机抽样集。
- 对非确定性任务进行多次重复，报告配对结果和关键用例退化，不只报告平均分。
- 新能力提升不能抵消 P0 安全或数据正确性退化。

## 跨维度观测项

在业务需要时额外记录：

- 首 Token 延迟、总延迟、吞吐量和超时率；
- 输入/输出 Token、工具调用次数和总成本；
- 可用性、重试率、限流和错误码；
- 同一输入重复执行的稳定性；
- 隐私、权限、审计和数据保留；
- 可观测性是否足以支持失败归因。
