## 必需字段

| 字段 | 填写要求 |
|---|---|
| 用例编号 | 稳定且唯一；建议 `TC-{系统}-{维度}-{序号}` |
| 测试维度 | 写主要维度；次要观测项放备注 |
| 场景说明 | 一句话说明用户场景、风险和本用例为什么存在 |
| 前置条件 | 模型/Prompt/数据/工具版本、参数、权限、对话历史和环境状态 |
| 输入内容 | 可直接执行；动态值用 `{占位符}` 并说明生成规则 |
| 预期行为 | 描述必须做到、允许做到及质量阈值 |
| 禁止出现的行为 | 写可观察的错误、违规、泄露或副作用 |
| 评分方法 | 判定器、Rubric、指标、阈值、重复次数和聚合方式 |
| 优先级 | P0、P1、P2 或 P3，并能追溯到业务风险 |
| 是否适合自动化 | 是、部分或否；注明自动化判定方式和人工环节 |
| 失败归因方向 | 模型、Prompt、数据、工具、系统、评分中的初步候选 |
| 备注 | 数据来源、关联需求、历史缺陷、限制和与相似用例的差别 |

推荐额外保存：

- 用例版本与负责人；
- 标签与适用模型；
- 测试夹具 ID；
- 实际输出和中间轨迹；
- 各评分项结果；
- 执行时间、耗时与成本；
- 缺陷 ID 和复测状态。

## 预期行为的写法

按任务性质选择预期形式：

1. **唯一事实**：写规范化后的正确值和允许的格式变体。
2. **有限集合**：列出可接受值或匹配规则。
3. **语义任务**：写必要要点、禁止错误和分级 Rubric，不限定固定措辞。
4. **结构化输出**：提供 Schema、字段语义和业务约束。
5. **工具任务**：写是否应调用、允许的工具、参数约束、调用顺序和副作用规则。
6. **RAG 任务**：写证据要求、引用要求、冲突处理和无答案行为。
7. **安全任务**：写拒绝边界、安全替代帮助和不得泄露的内容。
8. **Agent 任务**：写完成条件、预算、确认点、停止条件和可接受计划范围。

避免：

- 把示例答案当成唯一可接受措辞；
- 使用“回答合理”“效果较好”等不可判定描述；
- 在预期中加入输入没有提供的隐藏事实；
- 要求无法从日志或结果中观察的内部思维过程。

## 硬性规则与主观评分

### 硬性规则

适合程序化判定：

- JSON 可解析并通过 Schema；
- 必填字段存在且类型正确；
- 不包含密钥、个人信息或禁止内容；
- 必须/不得调用指定工具；
- 参数在允许范围内；
- 引用 ID 真实存在；
- 代码可编译并通过指定测试；
- 延迟、成本、调用次数不超过阈值。

先执行硬性门禁。P0/P1 硬规则失败时，通常直接判该用例失败；不要用语言流畅度补偿。

### 主观评分

适合 Rubric：

- 相关性、完整性、清晰度；
- 解释质量和可操作性；
- 摘要覆盖与信息组织；
- 风格、语气和用户体验；
- 开放式代码设计或计划质量。

将主观概念拆成互不重叠的评分项，并为每个分值提供锚点。

## Rubric 模板

可使用 0～3 四级评分：

| 分值 | 通用锚点 |
|---|---|
| 3 | 完全满足要求，无实质错误；仅有不影响使用的微小表达问题 |
| 2 | 核心正确且可用，但遗漏次要内容或存在轻微问题 |
| 1 | 部分相关，但有重要遗漏、明显错误或需要大量人工修正 |
| 0 | 未完成任务、核心错误、违规、不可用或产生危险行为 |

为具体任务改写锚点。例如“证据忠实度”应明确：

- 3：所有关键陈述均由给定证据支持；
- 2：核心结论有支持，存在不影响结论的轻微无依据表述；
- 1：至少一个关键陈述缺少支持或夸大证据；
- 0：核心答案与证据冲突、伪造证据或在无证据时确定作答。

### 聚合规则

明确：

1. 每项权重；
2. 硬性门禁；
3. 单用例通过阈值；
4. 维度通过阈值；
5. P0/P1 最大允许失败数；
6. 多次执行使用最差值、均值、中位数、通过次数或稳定率；
7. 是否要求统计显著性或置信区间。

不要只给总分。保留分项分数和失败原因。

## 自动化适用性

### 是

适用于：

- 精确值、枚举、正则、Schema；
- 代码编译与测试；
- 工具名称、参数和轨迹；
- 检索命中、引用映射；
- 延迟、成本、调用次数；
- 明确安全模式和敏感信息扫描。

### 部分

适用于先自动检查硬规则，再由人工或 Judge 评分语义质量。写清自动与人工边界。

### 否

适用于高度依赖业务判断、文化语境、创意质量或尚无可靠判定标准的任务。仍需提供人工 Rubric 和复核流程。

自动化用例应固定或记录：

- 输入数据与随机种子；
- 模型和参数；
- Prompt、知识库、工具和评分器版本；
- 重试与超时策略；
- 原始输出和中间轨迹；
- 判定器版本；
- 脱敏和保留策略。

## LLM-as-a-Judge

只在确定性判定不足时使用，并控制：

1. **位置偏差**：交换 A/B 顺序或随机化候选位置；
2. **冗长度偏差**：要求按内容证据评分，不奖励无关长度；
3. **自偏好**：避免用被测模型无校准地评自己；
4. **提示敏感性**：固定 Judge Prompt 和版本；
5. **不稳定性**：重复评分并记录一致率；
6. **知识偏差**：让 Judge 只使用指定参考资料；
7. **量表漂移**：使用已由人工标注的校准集；
8. **解释幻觉**：Judge 理由只能帮助复核，不能替代证据。

安排人工抽检：

- 全量复核 P0 失败和高风险通过样本；
- 随机抽取各维度、各分段样本；
- 复核 Judge 与确定性规则冲突的样本；
- 统计 Judge 与人工的一致率；
- 低一致率时停止依赖 Judge 总分并修订 Rubric。

## 通用示例

| 字段 | 示例 |
|---|---|
| 用例编号 | TC-CHAT-INST-001 |
| 测试维度 | 指令遵循 / 结构化输出 |
| 场景说明 | 验证模型能否按指定字段输出简短会议摘要 |
| 前置条件 | 模拟模型版本 v-test；温度 0；无外部工具 |
| 输入内容 | 将给定的虚构会议记录总结为 JSON，只包含 `decisions` 和 `actions` |
| 预期行为 | 输出可解析 JSON；只含两个指定字段；事实来自输入；行动项含负责人占位名 |
| 禁止出现的行为 | Markdown 包裹、额外字段、编造行动项、真实个人信息 |
| 评分方法 | JSON Schema 硬检查；事实一致性 Rubric 0～3；硬检查失败即失败 |
| 优先级 | P1 |
| 是否适合自动化 | 部分：结构自动检查，事实一致性人工或经校准 Judge 评分 |
| 失败归因方向 | Prompt、模型、评分 |
| 备注 | 仅使用虚构会议内容；与长文本摘要用例分开 |
