# 新手代码交付规范

此文件用于业务代码交付说明，不是 Session Handoff。

## 表达原则

- 只报告实际做过的操作；未运行的命令标为建议。
- 使用用户当前操作系统对应的路径和命令，不罗列多套系统版本。
- 不复制完整源码、长日志或与本次改动无关的项目说明。
- 不要求用户公开密钥、Token、Cookie 或完整连接字符串。
- 首次出现必要术语时用一句话解释。

## 最小交付结构

根据任务范围选择，不生成空章节：

1. **结论**：完成了什么，当前能否运行。
2. **关键文件**：只列本次修改文件及职责。
3. **验证证据**：命令、结果、覆盖范围和限制。
4. **运行或复现**：用户真正需要的最短步骤。
5. **风险与待办**：尚未验证或需人工确认的事项。
6. **Git/合并**：仅当用户明确需要时，转由 `$guide-gitlab-safely`。

分析、Spec 或只审查任务只交付当前阶段结论，不使用“代码已完成”等措辞。

## 运行步骤

每一步只包含：

- 目的；
- 执行目录；
- 一条命令或一组不可分割的安全命令；
- 正常结果；
- 最短验证；
- 失败时优先检查的位置。

命令必须来自当前项目的真实文档、脚本、锁文件或 CI，不凭经验发明。

只有当前改动需要时才说明运行时版本、依赖安装、配置、迁移、启动和停止；不要每次重复完整项目安装教程。

## 验证记录

使用简表：

| 命令/操作 | 证明目标 | 实际结果 | 限制 |
|---|---|---|---|
| | | | |

结果至少包含可复核的信息，例如测试数量、构建目标、关键字段或输出文件。

证据标签：

- `已实际验证`
- `仅静态检查`
- `合理推断`
- `尚未验证`
- `需要人工确认`

完整验证受阻时说明原因，并给一条最小补充验证路径。

## 常见问题

只列 0～3 个与当前改动直接相关的高概率问题。每项包含症状、优先检查位置和下一步；没有明确风险时省略，不输出通用报错百科。
